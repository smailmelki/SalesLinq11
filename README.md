# SalesLinq

برنامج مبيعات ومخزون ومحاسبة مبني باستخدام C# وWindows Forms وSQL Server.

## حالة المشروع

المشروع في مرحلة إعادة تنظيم واستكمال على الفرع `developer`. الفرع `master` محفوظ دون تعديل.

**الهدف الأساسي:** إزالة DevExpress بالكامل واستبدال عناصره بعناصر Windows Forms القياسية، مع الحفاظ على الوظائف المحاسبية والمخزنية وعدم تغيير بيانات قاعدة البيانات دون ترحيل واضح.

## التقنية الحالية

- C#
- Windows Forms
- .NET Framework 4.8
- SQL Server
- LINQ to SQL
- Argon2 لتجزئة كلمات المرور

## ما تم تحويله إلى WinForms القياسية

- شاشة إعداد الاتصال.
- شاشة تسجيل الدخول وإنشاء حساب المدير الأول.
- شاشة المخازن وقائمة المخازن.
- شاشة الخزن وقائمة الخزن.
- شاشة الأصناف وقائمة الأصناف.
- شاشة العملاء والموردين المشتركة وقائمتهما.
- شاشة المستخدمين وقائمة المستخدمين بعناصر WinForms القياسية.
- شاشة نماذج صلاحيات الوصول وقائمتها باستخدام `DataGridView` القياسي، مع إظهار صلاحيات كل إجراء متاح لكل شاشة.
- شاشة نماذج إعدادات المستخدم وقائمتها، مع إنشاء عناصر الإعدادات ديناميكياً باستخدام `CheckBox` و`ComboBox` و`NumericUpDown`.
- أساسان جديدان قابلان لإعادة الاستخدام: `NativeMasterForm` و`NativeMasterListForm`.

### ملاحظات على شاشة الأصناف

- استبدال عناصر DevExpress بعناصر WinForms القياسية و`DataGridView`.
- الإبقاء على بيانات نوع الصنف والفئة وطريقة حساب التكلفة والصورة والوصف وحالة النشاط.
- إدارة وحدات القياس ومعاملات التحويل وأسعار الشراء والبيع والخصومات والباركود.
- التحقق من تكرار كود الصنف واسمه والباركود ووحدات القياس.
- حفظ الصنف ووحداته ضمن معاملة قاعدة بيانات واحدة، وحذف الوحدات والصنف ضمن معاملة واحدة بعد التحقق من عدم وجود حركات مخزون مرتبطة.

### ملاحظات على العملاء والموردين

- تحويل شاشة البيانات المشتركة وقائمة العملاء/الموردين إلى WinForms القياسية.
- الإبقاء على نوع السجل (عميل أو مورد)، وبيانات الاتصال والعنوان وحد الائتمان ورقم الحساب.
- منع تكرار الاسم داخل نوعه؛ يسمح بوجود الاسم نفسه كعميل ومورد إذا كان ذلك مطلوباً.
- إنشاء الحساب المحاسبي وربطه بالطرف ضمن معاملة واحدة عند الإضافة.
- تحديث اسم الحساب عند تعديل الطرف ضمن المعاملة نفسها.
- منع حذف الطرف عند وجود قيود مرتبطة بحسابه، وحذف الطرف والحساب ضمن معاملة واحدة عند السماح بالحذف.

لا تزال شاشات أخرى، ومنها الفواتير والنافذة الرئيسية والتقارير، تعتمد على DevExpress أو على الأساسين القديمين. شاشة المستخدمين وقائمتها ونماذج صلاحيات الوصول وإعدادات المستخدم وقوائمها، وكذلك شاشة إنشاء المدير الأول، نُقلت إلى WinForms القياسية. تُنشئ شاشة التشغيل الأول حساب مدير واحداً فقط ضمن معاملة تسلسلية، وتحافظ شاشة المستخدمين على تجزئة Argon2، كما تسمح بترك كلمة المرور فارغة عند التعديل للإبقاء على كلمة المرور الحالية. نماذج إعدادات المستخدم تحفظ خصائص الإعدادات ضمن معاملة واحدة، مع تحويل القيم إلى أنواعها الأصلية قبل التسلسل للحفاظ على قيم التعدادات. لذلك لا تزال مراجع DevExpress موجودة في المشروع.

## بدء العمل

1. افتح الحل في Visual Studio.
2. تأكد من تثبيت .NET Framework 4.8 Developer Pack.
3. راجع إعدادات SQL Server من شاشة إعداد الاتصال.
4. لا تستخدم قاعدة بيانات الإنتاج أثناء اختبار التعديلات؛ استخدم نسخة احتياطية منفصلة.

لم يكتمل بعد استبدال جميع شاشات وتقارير DevExpress. لم يتم تأكيد بناء الحل واختباره بعد هذه التعديلات؛ لذلك لا تعتبر هذه النسخة جاهزة للنشر أو التشغيل الإنتاجي حتى إكمال التحويل وبناء الحل واختبار وظائف البيع والشراء والمرتجعات والمخزون والقيود المحاسبية.
