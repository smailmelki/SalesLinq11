# خطة استكمال SalesLinq وإزالة DevExpress

## المبادئ

1. العمل على الفرع `developer` فقط، وعدم دمج التغييرات في `master` قبل اكتمال الاختبارات ومراجعة الفروقات.
2. عدم تغيير مخطط قاعدة البيانات أو حذف بيانات المستخدمين دون ترحيل موثق ونسخة احتياطية.
3. عدم استبدال منطق المحاسبة أو المخزون بتخمينات؛ يجب أن تكون كل قاعدة عمل قابلة للاختبار.
4. استخدام عناصر WinForms القياسية (`Form`, `TextBox`, `ComboBox`, `DataGridView`, `TreeView`, `PrintDocument`) بدلاً من DevExpress، دون إضافة مكتبة تجارية بديلة.
5. تأجيل ترقية .NET Framework إلى ما بعد استقرار التحويل، لتقليل نطاق المخاطر.

## الوضع الحالي

تم تحويل إعداد الاتصال وتسجيل الدخول والمخازن والخزن والأصناف وقوائمها والعملاء والموردين وقائمتهما وشاشة المستخدمين وقائمتها إلى عناصر WinForms القياسية. شاشة المستخدمين تحافظ على تجزئة Argon2؛ عند تعديل مستخدم يمكن ترك حقل كلمة المرور فارغاً للإبقاء على التجزئة الحالية، كما تُمنع محاولة حذف حساب الجلسة الحالية. شاشة الأصناف تحفظ بيانات الصنف ووحداته ضمن معاملة واحدة، وتمنع حذف صنف له حركات مخزون. كما تحفظ شاشة العملاء والموردين الطرف وحسابه المحاسبي ضمن معاملة واحدة، وتمنع حذف الطرف عند وجود قيود مرتبطة بحسابه. لا تزال نماذج صلاحيات الوصول وإعدادات المستخدم والفواتير والنافذة الرئيسية والتقارير بحاجة إلى الترحيل، كما لا تزال الأساسان القديمان ومراجع DevExpress مطلوبة للشاشات التي لم تُنقل بعد.

لم يتم بناء الحل أو تشغيله بعد هذه الدفعة؛ التحقق الحالي مراجعة ساكنة للملفات فقط. يجب إجراء Build في Visual Studio على نسخة قاعدة بيانات اختبارية قبل اعتبار هذه الدفعة جاهزة للاستخدام.
